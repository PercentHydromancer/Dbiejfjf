## Главное: ИИ без API-ключей и без ручной установки

**Теперь можно просто опубликовать сайт и начать переписку.** Если серверные модели (Ollama/llama.cpp) не настроены, Malik GPT автоматически пытается загрузить открытую модель в браузере пользователя через Transformers.js и Hugging Face. Основная браузерная модель — Qwen2.5-0.5B-Instruct; резервная — SmolLM2-135M-Instruct. Никакие Groq/OpenAI API-ключи не требуются. Модели не входят в GitHub ZIP: при первом сообщении браузер сам скачивает веса модели (возможны сотни мегабайт). Нужны интернет и достаточно памяти устройства. Генерация на телефонах может быть **очень медленной**, а на некоторых устройствах не запустится вообще. После загрузки поддерживается браузерное кеширование, если оно разрешено устройством.

Порядок: **настроенная серверная модель → Qwen в браузере → SmolLM2 в браузере**. Нет искусственной задержки в 30 секунд, но это не значит, что вычисления мгновенные. Текст из браузера сохраняется в историю через защищённый серверный маршрут. Качество этих небольших моделей сильно ниже ChatGPT; это не доступ к OpenAI и не все возможности ChatGPT. Если оба браузерных движка недоступны, сайт покажет настоящую ошибку, а не фиктивный ответ.

Развернуть веб-интерфейс на Render можно с Build Command `npm install` и Start Command `npm start`. Для **постоянных аккаунтов** нужен `DATABASE_URL` от PostgreSQL. Без базы файловая система бесплатного Render может удалить историю при новом деплое. Для использования браузерных моделей переменные `OLLAMA_BASE_URL` и API-ключи не нужны.

# Malik GPT — облачные и браузерные ИИ без API-ключей

Самостоятельный проект с белым минималистичным интерфейсом в стиле современных чат-приложений. Это не ChatGPT и не копия его закрытых моделей, аккаунтов и инструментов.

## Настоящие функции

- Регистрация и вход с проверкой cookie, история чатов, поиск, переименование и удаление. Для Render поддерживается PostgreSQL через DATABASE_URL.
- Общение с **облачной анонимной моделью OVHcloud**, а также автоматическим резервом Puter.js (GPT/Gemini) и моделями в браузере. API-ключ разработчику не нужен. Ollama и локальные модели теперь **необязательны**.
- При ошибке одной модели Malik GPT пробует следующую **без искусственного 30-секундного таймера**. Время генерации и таймауты внешних процессов всё равно остаются.
- Режим «Код и файлы», скачивание текстового кода из ответов модели, ZIP из нескольких файлов.
- Независимый генератор стартового сайта: рабочие `index.html`, `style.css`, `script.js` и ZIP даже без локальной модели.
- Редактор текстовых файлов с сохранением на устройство.
- Кнопка «+»: загрузка текста, редактор и ZIP-файлы, заметки, экспорт переписки, запись голосового.
- Запись голосовых сообщений с микрофона и воспроизведение в чате. В браузерах с поддержкой Web Speech также доступна диктовка текста через «+», а ответы можно озвучить средствами браузера.
- Отдельный вход администратора и статистика пользователей, чатов и заметок — только с настроенными ADMIN_LOGIN и ADMIN_PASSWORD.
- Загрузка текстовых файлов в поле сообщения (до 120 КБ); заметки пользователя.
- Мобильная адаптация и белая тема, близкая по характеру к интерфейсу ChatGPT.

Кнопки не имитируют платные или недоступные функции: записать и прослушать голосовое можно, но автоматическая расшифровка речи/голосовой разговор с ИИ не подключены. Генерация изображений, платежи и интернет-поиск также не заявлены.

## Быстрый запуск на ПК (Ollama не нужна для облачного ИИ)

1. Установи [Node.js 20+](https://nodejs.org/). Ollama теперь необязательна.
2. По желанию установи [Ollama](https://ollama.com/download) и скачай модели, чтобы получить дополнительный локальный резерв:

```bash
ollama pull qwen2.5:3b
ollama pull llama3.2:3b
ollama pull gemma3:1b
ollama pull phi3:mini
```

3. Если ты используешь Ollama, запусти `ollama serve`.
4. В папке сайта:

```bash
npm install
npm start
```

5. Открой http://localhost:3000, зарегистрируйся и начни общение.

**Ollama необязательна.** Если не установлена, сайт попробует ИИ в браузере пользователя. Для более качественной и быстрой генерации можно дополнительно настроить Ollama на сервере.

При необходимости настрой переменные среды:

```env
PORT=3000
DATA_DIR=./data
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODELS=qwen2.5:3b,llama3.2:3b,gemma3:1b,phi3:mini
```

`OLLAMA_MODELS` — необязательный список приоритетных моделей. Другие установленные модели сервер также сможет использовать в качестве резерва. Это не платные API, но загрузка моделей занимает место на диске и требует памяти. Установи только те модели, которые подходят твоему компьютеру. Каждая модель автоматически определяется через Ollama и используется в качестве резерва.

## Docker Compose (ПК/VPS)

Есть `docker-compose.yml`: приложение и Ollama запускаются вместе, без публичного доступа к порту Ollama.

```bash
docker compose up -d --build
docker compose exec ollama ollama pull qwen2.5:3b
docker compose exec ollama ollama pull llama3.2:3b
```

Затем открой http://localhost:3000. На обычном CPU модели могут отвечать медленно. Для многопользовательского сервиса необходимы достаточные RAM, CPU/GPU и проверка производительности.

## Публикация на Render

**Для облачных запросов Ollama больше не требуется.** Бесплатный Render может запускать Node-сайт и делать HTTPS-запросы к OVHcloud. Однако анонимный бесплатный лимит на модель мал, и стабильную работу большого платного сервиса без расходов он не обеспечивает. **Если хочешь локальные модели на сервере**, Render Free не предоставляет для них достаточно ресурсов. Нужно запустить Ollama на собственном ПК/VPS (сервер и модель должны быть постоянно доступны) или выбрать платную инфраструктуру с необходимой оперативной памятью. Адрес Ollama задаётся через `OLLAMA_BASE_URL`. **Не публикуй Ollama без защиты на открытом порту**: используй приватную сеть/VPN, аутентифицированный прокси.

Для надёжного хранения аккаунтов, сессий, чатов и аудиосообщений теперь поддерживается **PostgreSQL**. В Render → Web Service → Environment добавь `DATABASE_URL` с адресом подключённой базы. При первом запуске таблицы `malik_store` и `malik_audio` создаются автоматически. Без `DATABASE_URL` сайт использует `DATA_DIR/store.json`; на Render Free этот файл временный, и **после деплоя может пропасть вход, аккаунты и история**. Чтобы это исправить, обязательно подключи PostgreSQL (либо постоянный диск). Хранение в PostgreSQL реализовано как единый JSON-документ для небольшой установки; для массового публичного запуска рекомендуется нормализованная БД.

## Проверка

- `/api/health` — статус приложения.
- Кнопка статуса в правом верхнем углу показывает доступные модели.
- Если Ollama не включена, сайт автоматически пробует Qwen и SmolLM2 прямо в браузере.
- Если модель не смогла ответить, вопрос сохранён и можно повторить попытку.

Проект — основа для самостоятельного развёртывания, а не прошедшая аудит система для большого числа пользователей. Для публичного запуска рекомендуется добавить внешнюю БД, журналирование, усиленные меры защиты и тесты под нагрузкой.

## Как работает ИИ без ключей

В этом проекте нет «бесплатного доступа ко всем ИИ по интернету» — для этого у большинства облачных провайдеров нужны API-ключи, учётная запись или иной механизм авторизации. Вместо них Malik GPT сначала проверяет **локальные серверные модели**, а при отсутствии работающей модели **использует браузерные модели на устройстве посетителя**. Модели вроде Qwen, Llama, Gemma и Phi запускаются на твоём компьютере или сервере. Сервер проверяет список реально установленных моделей и пробует следующую при ошибке первой. Если Ollama не установлена или ни одна модель не работает, сайт пробует две небольшие браузерные модели. Если и они недоступны, покажет честную ошибку.

## Дополнительные локальные источники без API-ключей

Malik GPT поддерживает **несколько локальных серверов Ollama** и **локальный OpenAI-совместимый сервер** (например, llama.cpp server). Это разные способы запускать открытые модели без сторонних API-ключей. При ошибке одной модели сайт пробует следующую; искусственной паузы между попытками нет. Однако если сервер занят или не отвечает, запрос может ждать сетевой таймаут.

Переменные среды:

```env
OLLAMA_BASE_URLS=http://127.0.0.1:11434,http://192.168.1.50:11434
OLLAMA_MODELS=qwen2.5:3b,llama3.2:3b,gemma3:1b,phi3:mini
LOCAL_OPENAI_BASE_URL=http://127.0.0.1:8080/v1
LOCAL_OPENAI_MODEL=local-model
```

Это **варианты**, а не предустановленные модели: скачай нужные в Ollama, например `ollama pull gemma3:1b` и `ollama pull phi3:mini`. Для llama.cpp нужен самостоятельно запущенный сервер с выбранной моделью. Не вводи адрес открытого незащищённого Ollama в интернет.

**Важно:** Render Free сам по себе не предоставляет вычисления для локального ИИ, но браузер пользователя может запускать небольшие модели, если хватает памяти и мощности. В этой версии нет платного облачного API-переключателя или поддельных ответов.


## Обновление: вход, голосовые сообщения и админка

В интерфейсе есть кнопка **«+»** со скачиванием переписки, открытием текстового файла, созданием проекта и заметками. Рядом с отправкой есть **🎙 Микрофон**. Запись использует MediaRecorder браузера и требует HTTPS или localhost и разрешения на микрофон. Нажми 🎙 для начала, затем ■ для отправки. Голосовые сохраняются и воспроизводятся в переписке. **Распознавания речи и ответа ИИ на аудио нет**, потому что отдельная локальная модель распознавания не подключена.

Админ-панель доступна из бокового меню и со страницы входа. Чтобы включить её, установи в Render → Environment:

```env
ADMIN_LOGIN=admin
ADMIN_PASSWORD=ПРИДУМАЙ_СВОЙ_ДЛИННЫЙ_ПАРОЛЬ
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DATABASE
```

Это **только примеры**, не вставляй вымышленный URL базы: скопируй настоящий Internal Database URL из своей базы PostgreSQL в Render. Пароль админа должен быть минимум 12 символов. Не добавляй реальные пароли и URL с секретами в GitHub. После сохранения Environment дождись рестарта или выполни Deploy latest commit.

Вход в обычный аккаунт и в админку раздельные. Админка показывает количество пользователей, чатов, сообщений, заметок и последние аккаунты. Она не показывает содержимое личных переписок и не содержит неподключённые платежи.

При развёртывании в Render выбери Node, **Build Command:** `npm install`, **Start Command:** `npm start`. Открой `/api/health`, чтобы увидеть `storage: "PostgreSQL"` при подключённой БД. Если видишь `storage: "local-file"`, постоянное хранение на Render ещё не настроено.


## Облачный ИИ без API-ключей — включён автоматически

Никакой API-ключ, Ollama или ручной выбор модели для базового облачного ответа не нужны. После деплоя используется цепочка:

1. OVHcloud AI Endpoints — `Olala-v1.0-mini-7A1B`, `Olala-v1.0-summarise`, `Qwen3.6-27B` (анонимный HTTPS API, без токенов; первые две Olala модели обычно имеют 2 запроса/минуту на модель и IP, условия провайдера могут измениться).
2. Если у тебя есть свои установленные Ollama / llama.cpp, сайт также пробует их как резерв.
3. В браузере Puter.js пробует `gpt-5.4-nano`, `google/gemini-3.5-flash-lite` и `google/gemini-2.5-flash`. **Puter использует User-Pays**: может предложить пользователю войти и потребовать оплату при превышении бесплатных ресурсов. Разработчик не вводит API-ключ.
4. Если Puter.js не смог ответить, сайт пробует Qwen/SmolLM в браузере. Скачивание весов модели требует интернет и память, поэтому на iPhone может не сработать.

При каждом переключении сообщения сохраняются; искусственная задержка на 30 секунд отсутствует. Из-за реальных сетевых таймаутов и ограничений скорость не гарантируется.

**Приватность:** текст вопросов, история последних сообщений и ответы могут передаваться внешним OVHcloud и Puter с собственными политиками обработки данных. Не отправляй в облачный ИИ секреты, пароли или чувствительные личные сведения. Сервис OVHcloud заявляет, что не хранит пользовательские данные, но Puter и модели, доступные через него, имеют собственные условия. Оператор сайта должен опубликовать свою политику конфиденциальности перед публичным запуском.

Если хочешь временно отключить анонимные OVHcloud запросы, установи `KEYLESS_CLOUD_ENABLED=false`. Это **не** отключает Puter.js на фронтенде. Для устойчивого коммерческого запуска нужны официальные условия с провайдерами и устойчивое хранение PostgreSQL.
